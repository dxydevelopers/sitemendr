# Sitemendr: Unified Identity & Product Flow Blueprint

## 1. Core Identity

Sitemendr is not a normal website agency and not just a SaaS dashboard.

Sitemendr is a modern digital business company that helps people and companies **build, repair, and grow online** through three connected divisions:

1. **Build**
   Custom website development, digital platforms, portals, brand websites, business tools, and high-end web experiences.

2. **Repair**
   Technical repairs, maintenance, security hardening, speed recovery, uptime monitoring, support tickets, and ongoing care for existing websites.

3. **Grow**
   Dropshipping programs, affiliate marketing systems, commerce storefronts, product strategy, niche direction, and Shopify-like online business setup.

The dashboard, AI systems, hosting, payment flow, and automation are delivery layers. They support the service, but they are not the first thing the public site should sell.

The public identity should feel like:

> Sitemendr gives businesses one serious place to build websites, fix digital problems, and launch commerce programs.

## 2. The Public Site Role

The public website is the front gate. It should create authority, explain the three worlds, and invite the user into a private workspace.

It should not immediately behave like a project builder.

The homepage should not expose every service detail, long questionnaires, internal process logic, or technical operations at once. It should guide the visitor toward account creation and dashboard entry.

Public site goals:

- Explain what Sitemendr is.
- Present the three service paths: Build, Repair, Grow.
- Show that the company is modern, visual, organized, and serious.
- Use visuals, video, icons, interface previews, and real work signals instead of too much text.
- Encourage users to create or access their workspace.

Primary public CTA direction:

- Create Your Workspace
- Enter Sitemendr
- Access Client Workspace
- Choose Your Path

Avoid public CTAs like:

- Start Building Now
- Initialize Protocol
- Start Project Immediately
- Generate Website

Those actions belong inside the dashboard after account creation.

## 3. The Dashboard Role

The dashboard is where the real Sitemendr work begins.

After a visitor creates an account or logs in, the dashboard should ask:

> What are you here to do?

The user chooses one of three paths:

1. **Build a custom website**
2. **Repair or maintain an existing website**
3. **Launch a dropshipping or affiliate commerce program**

From there, the dashboard opens the correct workspace.

Dashboard goals:

- Collect the right assessment data.
- Recommend the right service path or plan.
- Show previews, reports, roadmaps, or diagnostics.
- Handle payment or approval.
- Track the actual work.
- Keep messages, files, billing, support, and progress in one place.

The dashboard is the workshop. The public site is only the entrance.

## 4. Public-To-Dashboard Journey

The core user journey should be:

```text
Homepage
  -> Create account or log in
  -> Dashboard entry
  -> Choose Build / Repair / Grow
  -> Complete path-specific assessment
  -> Receive recommendation, preview, report, or roadmap
  -> Approve and pay
  -> Workspace becomes active
  -> Sitemendr executes and tracks the work inside the dashboard
```

This means the homepage should no longer open the full assessment flow directly. It may preview the paths, but the real assessment belongs inside the dashboard.

## 5. The Three Workspaces

### A. Build Workspace

For custom website development and digital platforms.

What the client sees:

- Project roadmap
- Milestones
- Asset upload area
- Design previews
- Staging links
- Feedback tools
- Launch checklist
- Messages with the Sitemendr team

Possible status flow:

```text
Brief -> Direction -> Design -> Build -> Review -> Launch -> Support
```

Visual language:

- Website mockups
- Brand boards
- Interface previews
- Roadmap timelines
- Design feedback pins

### B. Repair Workspace

For technical repairs, maintenance, and site protection.

What the client sees:

- Site health score
- Issue list
- Repair tickets
- Security checks
- Speed diagnostics
- Uptime monitor
- Activity log
- Monthly reports

Possible status flow:

```text
Diagnose -> Prioritize -> Repair -> Verify -> Monitor
```

Visual language:

- Health dashboard
- Before/after speed scores
- Security scan views
- Incident timeline
- Uptime graph

### C. Grow Workspace

For dropshipping, affiliate marketing, and commerce programs.

What the client sees:

- Niche assessment
- Product direction
- Storefront preview
- Product/category planning
- Affiliate offer setup
- Supplier or platform notes
- Commerce launch checklist
- Sales or campaign metrics

Possible status flow:

```text
Niche -> Offer -> Store -> Launch -> Promote -> Optimize
```

Visual language:

- Product grids
- Storefront previews
- Sales panels
- Affiliate campaign visuals
- Commerce dashboard elements

## 6. Homepage Structure

The homepage should feel like a modern product experience, not a stack of generic marketing cards.

Recommended section map:

### 1. Opening Hero: The Front Gate

Purpose: Establish the new Sitemendr identity.

Suggested direction:

> Build. Repair. Grow Online.
>
> Sitemendr brings custom websites, technical recovery, and commerce programs into one private workspace for serious digital business.

Visual:

- Full-screen cinematic video or motion background.
- Foreground interface preview with three live modes: Build, Repair, Grow.
- CTA to create/access workspace.

### 2. Three Paths

Purpose: Show the service divisions without dumping every detail.

Paths:

- Build: Custom websites and digital platforms.
- Repair: Technical fixes, protection, and maintenance.
- Grow: Dropshipping and affiliate commerce programs.

Visual:

- Three large application-like panels, not ordinary cards.
- Each panel should use icons, images, or videos that hint at the path.
- Each path links to deeper service explanation.

### 3. Work Happens Inside

Purpose: Explain the dashboard model.

Message:

> Sitemendr does not begin with a public form. Create your workspace, choose your path, and manage the work from inside your dashboard.

Visual:

- Dashboard preview.
- Left navigation.
- Active project switcher.
- Message thread.
- Roadmap, health score, or commerce preview.

### 4. The Operating Flow

Purpose: Make the process clear.

Flow:

```text
Create Workspace -> Choose Path -> Complete Assessment -> Review Plan -> Approve Work -> Track Delivery
```

This should be visual and compact, not a long text section.

### 5. Proof Without Over-Revealing

Purpose: Show capability without exposing every internal detail.

Use:

- Selected outcomes.
- Short testimonials.
- Visual case hints.
- Before/after indicators.
- Store, website, and repair examples.

### 6. Final Portal CTA

Purpose: Move user into the dashboard.

Suggested CTA:

> Create your Sitemendr workspace.

Secondary CTA:

> Explore services.

## 7. Tone And Messaging

The tone should sit between simple and premium.

Avoid language that feels too local:

- We build nice websites
- Start my project now
- Easy website setup
- We fix your site fast

Avoid language that feels too internal:

- Protocol
- Nodes
- Architecture matrix
- System integrity queue
- Operational infrastructure stack

Preferred language:

- Workspace
- Digital business
- Build path
- Repair path
- Commerce path
- Project roadmap
- Site health
- Storefront
- Launch plan
- Managed support
- Private dashboard

The public wording should be understandable, but still feel like Sitemendr is larger than a local web design shop.

## 8. Visual Direction

The new homepage should use meaningful visuals.

Visual rules:

- Use live video backgrounds where they support the section.
- Use real website, storefront, dashboard, workspace, commerce, repair, and monitoring imagery.
- Use icons where text is unnecessary.
- Reduce ordinary card stacks.
- Build sections like parts of an application.
- Let users understand through layout and visual cues before reading long copy.

Visual examples:

- Build section: website mockup, brand preview, design canvas.
- Repair section: site health monitor, speed test, security scan.
- Grow section: storefront, product grid, affiliate campaign, sales panel.
- Dashboard section: project workspace, messages, billing, support, roadmap.

## 9. Navigation Direction

Public navigation should support controlled discovery.

Suggested public nav:

- Home
- Services
- Workspaces
- Portfolio
- Pricing
- Contact
- Client Login

Possible service sub-navigation:

- Build
- Repair
- Grow

Authenticated navigation should shift to:

- Overview
- My Projects
- Messages
- Billing
- Support
- Resources
- Rewards
- Settings

## 10. Implementation Direction

Before redesigning the UI, update the product flow:

1. Homepage CTA should route to registration/login or workspace entry, not the full assessment modal.
2. First-time dashboard should present the Build / Repair / Grow path selector.
3. Assessments should be path-specific and happen inside the dashboard.
4. Public service pages should explain each division more deeply.
5. Pricing should map to the three paths and delivery model:
   - Hosted / managed
   - Self-hosted / ownership
   - Maintenance / support
   - Commerce program

This blueprint should guide the next homepage redesign and dashboard onboarding work.
